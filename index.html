Outrider draws a repository as one map. Every folder, file and function is a box sized by its lines and painted with its source. Zoom from the repo to a function, see where the commits are landing, and let your coding agents frame, paint and narrate the same map. Native, MIT, no account.

What it is

A code map, not a file tree.

A file tree tells you what exists. The map tells you how much of it there is, where it sits, what it looks like and how often it changes. Every folder, file and function is a box; a box's area is its line count; and as a box grows on your screen it goes from a dot to a name to a card to its own highlighted source. Zoom out and you are looking at the shape of the repository. Zoom in and you are reading the code.

Outrider draws and does not edit. Ctrl+Shift+E reveals a file in your file manager, and that is the whole hand-off today. At the whole-repository zoom you are reading names and colors, not code, and Outrider does not summarize: if you want prose, it comes from your agent as a marked note.

Your agent

Your coding agent drives the map through a CLI.

An agent frames a region, dims everything else, paints a metric, leaves a note beside a function or writes a guided tour you step through with the arrow keys. You answer by attaching comments to symbols; one command turns them into the agent's next prompt. Outrider draws the ground truth. Your agent narrates on top of it, and the narration is always marked as the agent's.

A tour, playing.

A tour is a view whose camera has steps. Each step frames a set or focuses a symbol, can push or pop a layer, and carries narration rendered beside the thing it describes. → and ← step; Esc leaves. The note in the frame was written by Claude Code through the run-outrider skill, and it is drawn in the marked narration style so you always know which text is the agent's.

Your half of the loop.

Press c on a symbol to attach a question or a change request. outrider-cli comments prompt renders every comment under its symbol's address, file and signature, and asks the agent to answer with a focused view or tour step and to propose code changes as diffs referencing those symbols.

The comments live in .outrider/comments.json inside the repository, so they travel with the checkout and an agent on another machine reads the same list.

“Comments are the user's half of the agentic loop: an agent presents a view or tour, the user annotates symbols with questions and change requests, and the accumulated list is turned into a prompt for the agent.”

crates/outrider/src/view/comments.rs, unedited.

There is no model inside Outrider, no API key and no network client. The agent is whichever one you already run; the shipped integration is a Claude Code skill and a CLI any agent can call. A view can paint a color only from a metric with a stated basis, so an agent can point and narrate and cannot paint an opinion.

Where the work lands

Watch where the work lands.

Every box carries a heat stripe for its git churn: the count of commits touching that path, ranked to a percentile within this repository, gray to red. The parts of the codebase that are changing most are the parts that glow, and you see it before you know their names. When a fleet is committing around the clock, the map is how you stay oriented.

Navigation

Find it by name, or walk to it.

Fuzzy file search and fuzzy symbol search, arrow keys that move across the map, Enter and Esc to step into and out of a box, and a history you walk with Alt+Left and Alt+Right. Eleven languages parsed: Rust, Python, C, C++, JavaScript, TypeScript, TSX, C#, GLSL, HLSL and Make. Markdown and everything else are on the map as chunks.

Linux, macOS and Windows. Windows binary. macOS and Linux build from source; Linux verified under WSLg, macOS unverified by the maintainer.

Before you run it

Questions you will ask before you run it.

Why not my editor's minimap?

A minimap is one file, shrunk. It shows the shape of the buffer you already opened and nothing about the files you did not. Outrider's unit is the repository: every box is a real file or function, its area is its line count, its stripe is its commit history, and you reach it by zooming rather than by knowing its path. The minimap is in your editor and Outrider is not: it does not edit and does not open your editor. Ctrl+Shift+E reveals a file in your file manager, and that is the whole hand-off today.

Why not a dependency-graph tool?

Graph tools draw architecture as built, and at repository scale that is a hairball with no stable place to stand. Outrider's spine is the folder tree, the one structure that survives agents rewriting the contents nightly, and the one you already know. Every symbol has a fixed position that only moves when its own ancestors change, so the same commit renders the same picture on any machine. Call and inheritance edges are a layer you turn on, and a separate graph space draws class diagrams and dependency pictures when you ask, drawn over or beside the map, never instead of it. Call edges are resolved from the syntax tree by name, not by a language server, so overloads and dynamic dispatch are approximate. If you need an exact cross-reference, use your language server. Outrider is for the shape.

Does it need an API key or send my code anywhere?

No. There is no model, no network client and no telemetry in the source. Caches for rendered textures and churn live in your OS cache directory, capped at 1 GB per project for textures, and Outrider never writes cache files into a repository it analyzes. The only things it writes into your project are the files you or your agent ask for under .outrider/: views, comments, project settings.

Which agent does it work with?

Whichever one you already run. The shipped integration is a Claude Code skill, run-outrider, and a CLI with 15 verbs that any agent or script can call over loopback JSON-RPC. A view is a JSON file, so an agent that can write a file can drive the map. Nothing in Outrider knows which agent is on the other end.

Does it run on my machine?

Linux, macOS and Windows, with settings under the usual per-platform config directory. One binary is published and it is for Windows. On macOS and Linux you build from source with Rust 1.89 or newer, and CI compiles and runs the tests on all three. The window has been run on Windows and on Linux under WSLg; no macOS run is recorded by the maintainer. It needs a GPU that can draw a window; a software rasterizer works and is slow.

Is this a product or a hobby?

An open-source tool, MIT, one maintainer, no company and no pricing page. 321 commits between 2026-07-05 and 2026-09-14, 49,597 lines of Rust across five crates, 656 tests, three tagged releases. It is a codebase written with coding agents by a person who needed to see what they wrote, and it is looked at through itself. It is under active development; expect rough edges and an issue tracker that answers. If you want a vendor with an SLA, this is not that.
